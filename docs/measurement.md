# 信号生成与测量边界

## 真实信号素材

`src/components/TestPlayer.tsx` 是可复用播放器；`src/core.ts` 定义 Signal、SignalEvent、FrameData、Diagnostics 和 RoundResult。运行中的大号 FRAME ID、EVENT ID、亮度方块、四角标记全部预先编码到视频中，**不使用 rAF 或 JavaScript 计时器生成信号帧**。rAF 仅用于预检浏览器回调节奏，计时器仅用于准备倒计时。

重新生成需要 Python 3、FFmpeg（包含 libx264 和 drawtext）以及 DejaVu Sans Mono Bold 字体。Linux 默认路径见脚本中的 `FONT`，其他系统可修改为自己的等宽字体路径。

```bash
npm run generate:signals
# 或只重生成一个帧率
python3 scripts/generate-signals.py --fps 60
npm run verify:signals
```

生成器以固定 LCG 种子 `0x56455952` 生成约 0.4–0.8 秒的变化间隔，向目标 FPS 的整数帧取整。帧从 000000 开始，前 1 秒 EVENT 000；每次变化是一个新事件，亮度交替。30/60/120FPS 各生成 100 事件的 1280×720 CFR H.264 素材，再无重编码裁剪出 20/50 事件版本。最后一个事件保留完整持续时间，视频不循环。约 13、31、63 秒/轮。

`public/signals/manifest.json` 记录每份素材的 SHA-256、帧数、时长、事件边界和亮度。验证脚本检查所有素材的逐帧 PTS、实际帧数、标称/平均帧率和摘要，并解码完整 100 事件素材检查所有编号区域唯一性及每帧检测方块的状态。生成结束必须验证并重新构建，清单和视频须一起发布。文件字节摘要可能随 FFmpeg 编码器版本不同而变化；种子与整数事件边界保持确定。

## 诊断与测量边界

- `requestVideoFrameCallback` 提供已提交给合成器的视频帧观察值，按素材媒体时间映射到事件清单。页面上的小号编号是低频回调快照；拍摄和分析应读取视频中的大号编号。
- `getVideoPlaybackQuality().droppedVideoFrames` 记录浏览器报告的解码/合成掉帧；回调媒体时间间隙、重复回调时间戳单独记录，**不等于物理 HDMI 掉帧或重复帧**。
- API 不可用、缓冲、退出全屏、刷新率不匹配会明确记录；页面切入后台、播放中断、改速或手动停止会标为未完成，不能冒充成功。
- 仅当填写的刷新率为源 FPS 的整数倍时，理论上可均匀保持源帧。浏览器回调节奏并非真实面板刷新率，更不能证明 HDMI 输出或显示扫描稳定；即使没有观察到异常，也没有确认物理逐帧输出。
- 30/60FPS 拍摄仍可使用，但采样精度低。120FPS 间隔约 8.33ms，240FPS 约 4.17ms；源 FPS、面板扫描、滚动快门与曝光仍限制准确性。部分手机 480/960FPS 模式无法连续拍完整一轮。
- 慢动作导出中的时间戳可能是减速播放时间。必须核实原始采样率和时间映射，不能凭播放速度换算延迟。
- 0 源帧差不等于 0ms。此测量得到指定显示环境中两条路径的可见延迟差，不一定是采集芯片内部延迟。
- 本站不声称测量真实扫描时间、HDMI 内部延迟，也不产生虚构的延迟统计。视频分析能力由用户自行选择的服务决定。

桌面推荐最新版 Chrome / Edge；Firefox / Safari 取决于平台 H.264 解码与视频帧回调支持。120FPS H.264 解码受设备性能限制。全屏失败时可降级为窗口播放并记录警告；移动端主要用于阅读引导。复制要求安全上下文（HTTPS/localhost）；不可用时会选中提示词供手动复制。
